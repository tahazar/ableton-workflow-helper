# Operator recipe: noise-perc (hat/perc from Operator's noise waveform)

**Sourcing note:** citations come from search-result excerpts of the named
pages, not full-page fetches. **All raw `device.param` values below are
unverified estimates.** Read the caveat block before applying.

## Craft

Operator has no dedicated noise oscillator. Noise is one of the five
selectable waveforms on any of its four oscillators (with sine, square,
sawtooth and triangle), per a search-aggregated description of Operator's
Wave chooser. Two Operator details matter for a percussion patch. First,
"the oscillator waveform choices are sine, sawtooth, rectangular and white
noise... [the] noise waveform is not real noise generated by a random
generator, but a looping noise sample" (an Ableton Forum thread on
Operator's wave shapes). That describes the "Noise Looped" waveform: a
fixed loop, which matters when layering several noise oscillators and
expecting independent randomness. A `device.get` dump shows Operator also
offers a separate "Noise White" waveform, which this recipe uses.
Second, layering matters more than the noise source: "by layering or
modulating a pitched sine wave with a noise oscillator, we can create DnB
snare noises, ping-y ride cymbals, or shimmery hihats". A sine "ping"
under the noise turns flat white noise into something that reads as a
specific piece of metal.

The core envelope principle for hats, from an Operator percussion-recipes
tutorial: "the key to a good hi-hat is an interplay of short and long
decay (emulating a closed and open hat)". It is one patch, with
Decay/Release the only difference between closed and open. An
Operator walkthrough gives a number for the shape: "for noise-based
synthesis, change OSC A's waveform to white noise and set the decay to
300ms and sustain to –inf dB... hi-hats use simple white noise with minor
adjustments to OSC A's ADSR" (dancemusicnw.com, "Ableton Operator 101").
A pair of MusicRadar/Ableton articles on noise-based hi-hats (built around
Analog, not Operator) gives a shorter, closed-hat number: "change the
waveform from a sine wave to white noise, then change the decay to 100ms,
the release to 90ms and sustain to –inf dB". It is cited only as a
cross-instrument data point for how much shorter a closed hat's decay is
than the 300ms Operator number, not as an Operator fact.

## Executable

```awh-operator-patch
name: noise-perc
device: Operator
params:
  Algorithm: 0    # display: Alg. 1, single-carrier shape: Osc-A alone, no FM routing needed for a noise-only percussion voice. Osc-B/C/D off in this base patch (see the sine-ping variant note below). Raw range 0-10, confirmed via `device.get`; raw 0 = Alg. 1.
  "Osc-A Wave": 21    # display: "Noise White". Range confirmed via `device.get`: min 0, max 22, 23 named waveforms (Sine/Sine 4 Bit/Sine 8 Bit/Saw 3-D/Square 3-D/Triangle/Noise Looped/Noise White/User). "Noise White" (index 21) is true random noise; "Noise Looped" (index 20) is the looping noise sample the craft section describes.
  "Osc-A Level": 1.0       # display: full noise output. Raw unverified.
  "Ae Attack": 0.0         # display: instant. Raw placeholder, unverified.
  "Ae Decay": 0.5          # display: ~300ms, the dancemusicnw Operator number for this patch type ("set the decay to 300ms"); leans open-hat. For a closed hat, shorten toward the 100ms Analog reference above (roughly half this raw value, unverified). Inferred param name (only Ae Attack confirmed). Display value sourced; raw mapping unverified.
  "Ae Sustain": 0.0         # display: -inf dB (silence), sourced ("sustain to –inf dB") from both cited walkthroughs. Raw 0.0 is likely Operator's floor for this parameter; unverified by readback.
  "Ae Release": 0.3         # display: short, ~90ms per the Analog reference ("release to 90ms"), used only as an ordering hint. Inferred param name; raw placeholder, unverified.
  "Filter Freq": 0.75       # display: highpass cutoff set high to remove low end a hat doesn't need (lowpassed noise reads as surf or wind, not a hat). Inferred param name, constructed display target (no sourced Hz value); raw unverified.
  "Filter Res": 0.3         # display: some resonance for a metallic "ping". Inferred param name; raw unverified.
  "Filter Type": 1          # display: Highpass. Range 0-4, quantized, 5 named types (Lowpass/Highpass/Bandpass/Notch/Morph), confirmed via `device.get`; Highpass = index 1.
  Volume: 0.7               # confirmed device.get name; the value is unverified.
playNotes: "1|1 F#1 1 v90"
```

**Sine-ping variant (not encoded above, prose only):** per the "layering a
pitched sine wave with a noise oscillator" citation, a second oscillator
(`Osc-B`, `Waveform` sine, `Coarse` a high ratio, `Level` low, its own
envelope decaying faster than `Ae Decay`) mixed under the noise is the
sourced route to a "ping-y ride" or "shimmery hihat" rather than a flat
noise hit. It is left out of the base patch because no source gives
numbers for that second layer.

## Raw values: unverified, read before applying

**Scale bug confirmed and corrected (2026-08-20) against a real `device.get` dump:** `Algorithm`'s real raw range is 0-10 (this recipe's 0 was already correct). `Osc-A Wave`'s real range is 0-22 (23 named waveforms, not 0-1); corrected to index 21 ("Noise White"), a confirmed waveform the original sourcing missed (only "Noise Looped" was cited). `Filter Type`'s real range is 0-4 (5 named types); corrected to index 1 ("Highpass"), an exact confirmed value replacing a guess that only rounded correctly by luck. `Filter Freq` (0-1) and `Filter Res` (0-1.25, close enough to the assumed 0-1 that 0.3 stays reasonable) were confirmed to need no correction.

Standing caveat (same estimation method as the other Operator recipes):
**every continuous raw value above is an unverified estimate, not a
measurement.** The quantized indices (`Algorithm`, `Osc-A Wave`,
`Filter Type`) are confirmed; no continuous raw↔display pair has been read
back into this repo. Apply,
listen against the display comments, correct, and record observed
raw↔display pairs here. This entry has better display-value grounding
than most Operator recipes (the 300ms decay and -inf dB sustain are
sourced numbers, not constructions), but the raw values that produce them
are guesses: no Operator ms→raw or dB→raw curve exists in this repo. The
envelope times are the weakest link; probe them before trusting anything
downstream.

## Param naming: verified vs inferred

- **Verified**: `Algorithm`, `Osc-A Wave`, `Filter Type`, `Filter Freq`,
  `Filter Res` (names and ranges confirmed by `device.get`), plus
  `Osc-A Level`, `Ae Attack`, `Volume`.
- **Inferred**: `Ae Decay`, `Ae Sustain`, `Ae Release`. `awh op apply`
  must validate every name against a live `device.get` dump before
  writing, and the envelope params are the first thing to hand-verify in
  Live.
